# 本地反思聊天 · 第一版

2026-09-11，Linus 通过一段产品体验对话确认：完整聊天自动保存在本机；回顾由用户修改、确认后留下。

## 体验约定

- 直接开始表述，不用先选择情绪类别或准备话题。
- 可以围绕经历、情绪、困惑自然聊天。AI 先确认理解，表达有依据的不同看法，不机械附和。
- 不喜欢凭空回忆时，给明确标为假设的具体情境供辨认。
- 提问、倾听、复述和独立观察交替进行。借鉴苏格拉底式提问和 CBT 对情境、想法、情绪、行为的区分；不预设用户有认知错误，不把自我描述固化为人格标签。
- 当理解已足够清楚、用户疲惫或希望停止时，主动提供待确认回顾；用户也可手动要求整理。12 个用户回合未形成新回顾时，请模型收束。
- 允许修改回顾或继续聊。只有用户明确确认，才将一段反思呈现为一条记忆。

## 数据与失败行为

`PENSIEVE_DATA_DIR` 默认为项目 `.pensieve/memories/`。

- 原有独立文字存档：`<id>.json`，维持兼容。
- 反思聊天：`sessions/<session-id>.json`。一个原子写入文件包含完整消息、带来源消息 ID 的 AI 回顾草稿、用户确认的回顾及其后续修改/归档/恢复历史。
- 每条消息含稳定 ID、角色、原文、记录时间；不静默裁剪原始文字。先落盘用户消息，再请求 AI；失败可重试，重复提交相同 ID 不重复追加。
- 确认回顾与会话完成状态在同一文件中原子更新。记忆列表从确认记录读取，无跨文件半完成状态。
- AI 草稿保留，不替代原始聊天。确认回顾后的修改产生新版本，完整聊天保持原貌。
- 导出包含独立存档、完整会话、未确认草稿和确认历史。完整备份应复制整个数据目录。

## AI 连接

本机后端从项目 `.env.local` 读取 `OPENAI_API_KEY`；`AI_CHAT_MODEL` 可配置，默认沿用已有项目的 `gpt-4o-mini`。密钥不传给前端、不写入记忆。

用户首次发送时明确开启 AI（或在设置中开启）后，这个浏览器的后续聊天使用 AI；设置可关闭。每次只将当前会话消息发送至 OpenAI；不自动检索或发送其他会话。使用 Chat Completions，显式 `store: false`，不创建云端 conversation/thread。

这不等于提供商零留存：详见 [OpenAI 数据处理说明](https://developers.openai.com/api/docs/guides/your-data)。本地保存和云端推理是两件分别可见的事情。尚未配置密钥时可存消息、手写回顾；不会伪造 AI 回复。

本版消息每条最多 20,000 字符；一次 AI 请求最多 80,000 个消息内容字符，超出会明确提示，原文仍完整保存。独立文字存档仍支持 500,000 字符。同一数据目录只运行一个本地服务。

## 2026-09-12 · AI 连接排障

新增可选 `OPENAI_PROXY_URL`，供本机后端经指定 HTTP(S) 代理连接 OpenAI；不更改操作系统代理，不自动改变其他应用的网络配置。

当前机器直连超时，使用其现有本机代理后已收到 OpenAI 响应。首次真实合成测试返回 `401 / invalid_api_key`；用户更新密钥后重试，返回 `429`、`code: credit_balance_exhausted`、`type: insufficient_quota`。这两次连接阻塞记录保留供追溯。密钥未显示或写入仓库，个人记忆未用作测试。

界面会区分无效密钥、API 余额用尽、其他额度不足、频率限制和网络失败，错误信息不回传提供商原始报文。额度判断兼容 `insufficient_quota` 类型下的细分错误码，避免把余额用尽误报为请求太频繁。

用户再次更新配置后，使用本机当前配置的 `gpt-5.4-mini`，经应用实际的 `createReflectionAI().reply` 调用成功。合成测试返回「连接测试成功。」，结构化结果通过校验，`review` 为 `null`。本地应用已重启以加载这份配置；此次测试未写入用户记忆目录。此次验证确认模型请求可以成功，尚不代表完整反思对话或 AI 回顾质量已验收。

## 2026-09-12 · 界面第一步：在当前区域收尾

- 进入回顾时，聊天输入区原地切换为「先聊到这里」和可编辑的回顾；聊天记录收起为「回看这段聊天」，避免同时提示用户继续输入和确认回顾。
- 回顾加载完成后，焦点与视线移到回顾区域；长回顾的编辑框限制可见高度，窄屏为底部导航留出空间。
- 「继续聊」恢复输入区并聚焦输入框，不自动请求 AI；「稍后再看」回到新聊天，原会话仍在历史中，未确认草稿不进入记忆。
- 暂缓确认、开启新聊天、切换会话或继续聊时，如回顾文字有修改，先通过本机 `/api/sessions/:id/review-draft` 保存成标明用户来源的新草稿，保留 AI 原稿。保存失败留在原处并保留编辑内容。修改尚未通过这些操作保存时，直接关闭页面仍只保留之前的草稿。
- 新接口校验当前草稿 ID，重复保存相同用户草稿不会新增版本；手写回顾也可稍后确认。导出明确区分 AI 草稿和用户修改。
- 提示词要求生成回顾时明确收尾、不再追问，不以解决问题或获得新发现为结束前提。原先的用户主动整理和 12 个用户回合的收束规则保持。

## 2026-09-12 · 简化入口与本机日常使用

- 首页突出开场白与输入区；存储位置、导出、模型和备份信息移到设置。侧边历史列表显示首句、日期与「可以接着聊／回顾待确认／已存为记忆」状态，支持搜索开头；窄屏用底部「聊天／历史／记忆／设置」。
- 聊天减少重复容器，用户原文用浅色气泡，AI 回复直接排版，正文增加行距，时间弱化。回顾仍原地替代输入区。
- 首次发送在实际请求之前说明云端数据去向，提供「开启 AI 并发送」与「先只保存原文」。浏览器只保存这一项偏好，不缓存原文；清除浏览器存储后会重新询问。设置关闭 AI 后保持本机记录模式，原有聊天保留；没有同意时不请求模型。
- `npm run start:local` 或根目录 `打开 Pensieve.command` 在后台启动本机服务，重复打开复用已验证的服务。`npm run stop:local` 校验服务身份后正常停止并完成备份。`npm run local` 保留开发时的前台运行方式；不创建开机启动项，不发布到云端。
- 启动器以私有文件保存临时访问令牌，只用于本机服务；不把 API Key 写入运行记录。日志超过 2 MB 时在下次启动轮换一份。自定义端口和运行目录供隔离验证使用；同一记忆目录仍只能运行一个服务。
- 自动快照在启动、成功写入后的短暂合并窗口和正常停止时执行。只复制记忆 JSON，跳过密钥、令牌与备份自身；相同内容不重复存。临时目录写入并刷盘后整体重命名，保留最近 20 份与最近 30 个有备份 UTC 日期的每日最后一份。各会话文件自包含且原子替换，快照不保证多个独立会话恰好来自同一瞬间。
- `/api/backups` 需本地令牌，可主动备份；设置展示备份时间或失败。失败不会撤销已保存原文。快照在同一磁盘上，异地/外置盘备份仍需自行安排。
- `npm run restore:local -- <快照> <新目录>` 校验清单、文件 SHA-256 和允许的相对路径，拒绝符号链接文件、篡改文件及已存在的目标目录；不会自动覆盖或切换当前数据目录。

验收使用临时目录和合成内容：后端备份与恢复、内容去重、停止前刷新、写入自动触发、错误提示、保留规则；启动器重复打开复用进程、正常停止、CLI 恢复后逐文件一致；浏览器桌面与 631 × 789 窄屏的首页、历史列表、回顾暂存后重新打开和刷新、设置备份、关闭 AI 后刷新保留选择。个人记忆未用于测试，模型回复使用合成桩，未为本轮界面验证调用真实模型。
