# 原材料导入

产品来源：[Institute 中的原话与范围确认](/Users/linuslin/Developer/linus-institute/01-Lab/Projects/Pensieve/Notes/Product-Definition/Raw-Material-Import-2026-09-13.md)。本次实现 Pensieve 内的 ZIP、Markdown 和纯文字入口；不整合 Institute，不调用 AI，不建立跨端同步。

## 如何使用

启动本机版或手机版，打开导航中的「原材料」。

1. 选择 `.zip`、`.md`、`.markdown`、`.txt`，或直接粘贴。来源和原始日期可留空。
2. 预览文件范围和可读内容，然后保存。ZIP 的按钮明确为「保存整个 ZIP」：它会保留文件中所有聊天、账号资料、附件及未知字段。如果只需要部分讨论，应先准备只含目标内容的文件，本版不提供按会话裁剪 ZIP。
3. 在已保存列表重新打开。可搜索文件名／来源／原始日期；打开一份原件后可搜索其中的讨论标题和文字。
4. 「下载原始文件」取得收到的原始字节；「下载可恢复备份」得到含原件、来源和校验信息的 `.pensieve.json`，可从同页「恢复原材料备份」恢复到 Mac 或手机。
5. 将备份另存到独立设备或你信任的位置。浏览器交付下载、数据保存和完成独立备份是不同状态；应用没有验证文件最终被存到哪里。

手机与 Mac 各自保存，不自动同步。导入入口仅适用于现有本机／手机个人模式；旧的云端账号模式没有增加导入 API。推送代码不等于部署手机版。

## 原件与阅读视图

- 原件格式 `pensieve-raw-v1`：原始字节（Base64）、收到的文件名、输入方式、文件类型、用户补充的来源／日期、导入时间、字节数及 SHA-256。
- 原始日期未知时保留 `null`；用户仅提供年月日时保留日期精度，不补成当前时间。粘贴按收到的片段保存，不推断发言人或伪称完整聊天。
- 记录 ID 是原件摘要与类型、输入方式、来源、原始日期的组合摘要。同一内容与来源重试不增加副本，改文件名也不会重复；内容更新或已知来源／日期不同会另存一份。单个会话和文字段落不会跨包自动合并。
- 阅读视图 `parser_version: 1` 每次从原件生成，不作为权威保存数据。后续更换解析器或增加 AI 派生内容，不需要重搬原件。
- Markdown/TXT 支持 UTF-8，以及带 BOM 的 UTF-16 LE/BE；保留原始换行、空白和文件字节。编码不明时保存原件并提示，避免用替换字符损毁正文。
- ZIP 识别任意目录下的 Markdown/TXT，以及 `conversations.json`、`conversations-1.json`、`conversations_1.json` 等带编号文件中的会话数组／`conversations` 包装／单会话 `mapping` 结构。
- ChatGPT 的每个节点均进入阅读视图，包括分支、未知角色和非文字内容。节点保留源顺序并显示父节点，**不是伪造的一条时间线**。非文字内容显示来源 JSON；全部字段、分支关系和实际附件仍在 ZIP 原件中。附件本身暂不在应用中打开，缺失的附件不会被创造出来。
- 无法解析的 JSON、其他格式和超出 5,000 篇阅读上限的内容在范围／提示中标为未展开，原包完整保留。页面对单篇先展示 60,000 字符，并明确提供完整文字下载；不截断保存的数据。
- 所有文本由 React 以纯文字呈现，不执行 Markdown/HTML，也不从 ZIP 路径解压到磁盘。

[OpenAI 官方导出说明](https://help.openai.com/en/articles/7260999)和[会话文件说明](https://help.openai.com/en/articles/9106926)确认了导出 ZIP／会话 JSON 的途径，未规定稳定字段协议。本次仅使用合成材料验证已识别结构，尚未取得用户的实际导出；不能据此承诺每种 ChatGPT 导出变体都能生成阅读视图。未识别结构仍可作为原件保留。

## 存储、失败与恢复

### Mac

- 存储位置为 `PENSIEVE_DATA_DIR/materials/<id>.json`，默认 `.pensieve/memories/materials/`；数据目录不进入 Git。
- 保存前完成解析及 ZIP 完整性检查。原件和来源同处一个文件，临时文件以 `0600` 写入并 fsync，通过不覆盖已有路径的硬链接原子发布，再同步目录并重新读取、核对原始字节摘要。并发重试保留先保存的原件；失败后可安全重试。
- 自动／手动快照现在包含 `materials/*.json`。备份前核对原件 SHA-256；恢复同时验证快照清单与原件格式／摘要，路径只允许受控的记录名，不接受符号链接或路径穿越。
- 完整快照仍通过 `npm run restore:local -- <snapshot-directory> <new-data-directory>` 恢复到新目录；不会覆盖当前库。原有聊天／记忆快照继续可恢复。
- 单份可恢复备份也可直接通过应用恢复。备份清单 SHA-256 检测意外损坏，**不是加密或身份认证**；请妥善保管含原文的备份。

### 手机

- 现有 IndexedDB `pensieve-phone-v1` 升到数据库版本 2，增加 `materials`，保留原有 `sessions` 和 `entries`。每次写入等待严格持久性事务完成后再报告成功；浏览器配额或存储失败时保留预览供重试。
- 完整备份格式升级为 `pensieve-phone-v2`，包含原件及每份清单校验值；仍接受不含原材料的旧版 v1 备份。旧应用会拒绝 v2 格式，不会静默跳过原材料。
- 恢复前验证全部原件；新增内容在一个事务中写入，任何同 ID 的不同记录使整次恢复取消，原有数据不覆盖。单份原件备份跨 Mac／手机可恢复。
- 浏览器数据仍可能因清理网站、配额或设备损坏而丢失；持久存储权限不替代独立备份。

## 大小与支持边界

每份原件最多 25 MiB，ZIP 最多 2,000 个条目、单个展开文件最多 25 MiB、总展开最多 100 MiB。限制在 ZIP 声明大小和实际流式输出两处检查，全部文件校验 CRC；加密、损坏、不安全／重复路径的 ZIP 整份拒绝，页面不显示“已保存”。不递归展开嵌套 ZIP。

单份原件备份文件上限 36 MiB；手机完整备份导出和恢复统一限制 200 MiB，过大时提供不含原材料的聊天／记忆备份，并提示逐份下载原材料备份。大规模资料库的分块备份、后台增量索引、按会话选择与自动关联为后续工作。

解析器是浏览器安全的共享 TypeScript 模块，位置在 `backend/src/imports/`；前端用 Worker 解析，避免 ZIP／JSON 阻塞页面。ZIP 使用 [zip.js](https://gildas-lormeau.github.io/zip.js/api/classes/ZipReader.html) 流式读取，不需要上传到第三方服务。

## 验证

仅使用临时目录、合成聊天和合成附件，不读取 `.pensieve/` 或用户私人记忆：

- 后端：保存与服务重启重读、2 MiB 以上请求、认证、私有文件权限、并发幂等、来源日期区分、更新保留、带编号的 ChatGPT JSON、所有分支／角色、未知格式保全。
- ZIP：CRC 损坏、截断、加密、路径穿越、虚假声明大小和输入上限失败；全部失败发生在原件发布前。
- 恢复：Mac 快照空目录恢复、单份原件跨存储恢复、原始字节与来源校验、损坏原件不成为有效快照、磁盘失败重试。
- 手机：v1 数据库升级和旧备份兼容、离线导入、重复导入、完整 v2 备份恢复、坏原件在写入前拒绝、冲突事务回滚。
- 页面：保存前预览、精确保留 Markdown 与粘贴空白、失败后保留预览、ZIP 整包范围告知、备份校验后再恢复。

验证命令：`npm test --workspace backend`、`npm test --workspace frontend`、`npm run typecheck --workspaces`、`npm run build:backend`、`npm run build:mobile`。
